찾아본 결론부터 말하면, 있습니다. 다만 지금 문헌은 아직 세 갈래로 나뉘어 있습니다. 하나는 Google A2A 프로토콜 자체의 보안성을 보는 논문, 다른 하나는 OpenClaw 같은 로컬 개인형 에이전트 런타임의 보안성을 보는 논문, 세 번째는 Claude Code·Codex CLI·Gemini CLI 같은 코딩/컴퓨터 점유형 에이전트의 skill·tool·파일 시스템 공격면을 보는 논문입니다. “OpenClaw/Claude Code/Codex를 실제 Google A2A 어댑터로 연결한 뒤 로컬 머신 점유 위험까지 실험한 단일 논문”은 아직 드뭅니다. 하지만 그 위험모델을 구성하는 핵심 논문들은 이미 꽤 나와 있습니다.

그리고 표기상으로는 사용자가 말한 “오픈 클로”가 논문들에서는 주로 OpenClaw로 나옵니다.

가장 직접적인 A2A 논문은 A2ASecBench: Understanding the Security of Agent-to-Agent Communication in Multi-Agent Systems입니다. OpenReview 기준으로 ICLR 2026 포스터 논문이며, Google A2A 기반 다중 에이전트 시스템을 대상으로 한 첫 보안 벤치마크라고 주장합니다. 이 논문은 A2A 프로토콜의 에이전트 발견, AgentCard, 태스크 생명주기, 산출물 전달 같은 요소를 공격면으로 보고, AgentCard Spoofing, Capability Cloaking, Cycle Overflow, Half-Open Task Flooding, Agent-Side Request Forgery, Artifact-Triggered Script Injection이라는 여섯 가지 공격을 정의합니다. 여행·의료·금융 같은 공식 A2A 데모 도메인에서 실험했고, 기본 보호장치만으로는 공격이 효과적으로 통과한다고 보고합니다. ([openreview.net][1])

이 논문은 질문에 가장 가까운 “A2A로 연결했을 때 생기는 보안 위협” 논문입니다. 특히 로컬 에이전트 맥락에서 중요한 것은 AgentCard Spoofing과 Capability Cloaking입니다. 로컬 컴퓨터에 접근 권한이 있는 에이전트가 A2A 네트워크에 붙으면, “나는 단순 캘린더 에이전트다”라고 소개하면서 실제로는 파일 읽기, 쉘 실행, 브라우저 조작, 토큰 접근 같은 능력을 숨길 수 있습니다. 또 Artifact-Triggered Script Injection은 한 에이전트가 생성한 결과물이 다른 에이전트의 실행 환경에서 코드나 스크립트처럼 해석되는 위험을 다루므로, Claude Code나 Codex CLI처럼 로컬 파일과 실행 컨텍스트를 만지는 에이전트와 연결될 때 특히 위험합니다. ([SaFoLab-JHU][2])

OpenClaw 쪽에서 가장 중요한 논문은 A Systematic Taxonomy of Security Vulnerabilities in the OpenClaw AI Agent Framework입니다. 이 논문은 2026년 3월 arXiv에 올라온 OpenClaw 보안 취약점 분류 논문이고, OpenClaw 관련 190개 보안 권고를 분석해 아키텍처 계층과 신뢰 경계 위반을 기준으로 분류합니다. 초록에서 특히 강하게 말하는 부분은, OpenClaw에서 LLM tool call이 호스트 OS까지 이어지는 unauthenticated RCE 경로, 취약한 exec allowlist, 악성 skill의 2단계 dropper, 그리고 “각 계층별 신뢰 검사가 통합 정책 경계로 묶이지 못한다”는 문제입니다. ([arXiv][3])

이 OpenClaw taxonomy 논문이 질문과 거의 맞닿는 지점은 inter-agent communication / inter-session contamination입니다. 논문은 OpenClaw의 sessions_send가 한 에이전트 세션의 프롬프트를 다른 세션으로 라우팅하면서, 그것을 별도 신뢰 등급 없이 일반 user role로 저장한다고 지적합니다. 즉 한 에이전트에서 오염된 지시가 다른 에이전트로 넘어가도 “외부 에이전트가 보낸 불신 입력”으로 표시되지 않고, 대상 에이전트 입장에서는 사용자 지시처럼 처리될 수 있습니다. 이건 Google A2A의 정확한 구현은 아니지만, A2A로 로컬 에이전트들을 연결할 때 발생할 수 있는 핵심 위험과 구조가 거의 같습니다. ([arXiv][3])

그다음으로 봐야 할 OpenClaw 논문은 ClawWorm: Self-Propagating Attacks Across LLM Agent Ecosystems입니다. 이 논문은 OpenClaw의 지속 설정, 로컬 작업공간, tool-execution 권한, Telegram·Discord·WhatsApp 같은 메시징 채널, skill marketplace를 공격면으로 보고, 자기복제형 worm 공격을 실험합니다. 논문은 공격자가 악성 지시를 설정이나 skill, 메시지 흐름에 심어두면 재부팅 후에도 실행되고, 다른 피어로 전파될 수 있다고 주장합니다. ([arXiv][4])

ClawWorm 논문이 로컬 A2A 위협에서 중요한 이유는 단순합니다. A2A는 “에이전트끼리 메시지를 주고받는 통로”이고, OpenClaw 같은 로컬 개인형 에이전트는 “실제 컴퓨터 권한을 가진 실행 주체”입니다. 둘이 결합되면 프롬프트 인젝션이 그냥 답변 오염으로 끝나지 않고, 설정 오염, skill 오염, 파일 시스템 접근, 메시징 채널 전파로 확장될 수 있습니다. ClawWorm 실험은 180회 trial에서 전체 attack success rate 0.85를 보고했고, 특히 skill supply-chain poisoning 벡터의 성공률을 0.95로 보고합니다. ([arXiv][4])

또 하나의 OpenClaw 논문은 Uncovering Security Threats and Architecting Defenses in Autonomous Agents: A Case Study of OpenClaw입니다. 이 논문은 OpenClaw가 OS-level 권한을 갖는다는 점에 주목하고, prompt injection 기반 RCE, 순차적 tool attack chain, context amnesia, supply-chain contamination을 주요 위협으로 분석합니다. 방어로는 FASA라는 zero-trust agentic execution 구조, 동적 intent verification, reasoning-action correlation, ClawGuard 같은 방어 체계를 제안합니다. 논문 내부에는 다중 에이전트 환경에서 악성 지시, 간접 prompt injection, memory pollution이 에이전트 사이로 전파되는 것을 막기 위한 Agent-to-Agent Protocol Inspection도 언급됩니다. ([arXiv][5])

A2A·MCP·기타 에이전트 프로토콜을 비교한 논문으로는 Security Threat Modeling for Emerging AI-Agent Protocols: A Comparative Analysis of MCP, A2A, Agora, and ANP가 있습니다. 2026년 4월 arXiv v2 기준 논문이고, MCP, A2A, Agora, ANP를 대상으로 인증, 발견, namespace, provenance, least privilege, DoS, 업데이트·롤백, 공급망 무결성 같은 축에서 비교합니다. A2A에 대해서는 Google이 2025년 4월 소개한 프로토콜로 설명하고, HTTPS/SSE/JSON-RPC, OAuth2/JWT, AgentCard, task lifecycle, artifact를 주요 구성요소로 봅니다. ([arXiv][6])

이 비교 논문의 실질적 메시지는 “A2A가 OAuth2/JWT를 쓴다고 해서 충분히 안전한 것은 아니다”입니다. 동적 발견 구조에서는 rug-pull 공격이 가능하고, 런타임 워크플로가 중간에 바뀌는 workflow shadowing은 MCP와 A2A 모두에 영향을 줄 수 있으며, broad scope나 long-lived token이 있으면 권한 오남용 위험이 커진다고 봅니다. 특히 A2A와 MCP가 연결되면, A2A 쪽 신원·권한 혼동이 MCP tool 실행으로 이어질 수 있기 때문에 “에이전트 신원”과 “도구 제공자 신원”을 강하게 묶어야 한다는 결론으로 읽는 게 맞습니다. ([arXiv][6])

Claude Code, Codex CLI, Gemini CLI 같은 로컬/CLI형 에이전트와 직접 관련된 논문들도 있습니다. Skill-Inject: Measuring Agent Vulnerability to Skill File Attacks는 Claude Code, Gemini CLI, Codex CLI를 대상으로, 공격자가 정상 skill 확장 파일 안에 악성 지시를 넣었을 때 에이전트가 얼마나 취약한지 측정합니다. 이 논문은 데이터 유출, 파괴적 파일 조작, 랜섬웨어 유사 행동, 원격 셸 다운로드 같은 harmful instruction을 다루며, 일부 조건에서 최대 80%의 attack success rate를 보고합니다. ([arXiv][7])

비슷한 축의 논문으로 Supply-Chain Poisoning Attacks Against LLM Coding Agent Skill Ecosystems도 중요합니다. 이 논문은 Claude Code, OpenHands, Codex, Gemini CLI를 대상으로 third-party skill marketplace의 보안 문제를 봅니다. 저자들은 문서·템플릿·예시 안에 악성 논리를 숨기는 DDIPE 공격을 제안하고, 15개 MITRE 범주에서 1,070개 adversarial skill을 만들어 평가합니다. Claude Code는 다층 review, Codex는 sandbox, Gemini는 safety filtering 등 각기 다른 방어 구조를 갖지만, 논문은 여전히 우회 가능성이 있다고 보고합니다. ([arXiv][8])

또 Malicious Agent Skills in the Wild: A Large-Scale Security Empirical Study는 Claude Code, Codex CLI, Gemini CLI 같은 생태계에서 skill이 빠르게 늘어나는 상황을 실증적으로 다룹니다. 논문은 커뮤니티 registry에 3개월 만에 98,000개가 넘는 skill이 생겼고, 보안 검토 없이 배포되는 경우가 많다고 지적합니다. 문서에 보이지 않는 “shadow feature”가 고급 공격에서 드러나는 문제도 다룹니다. ([arXiv][9])

컴퓨터를 직접 조작하는 CUA, 즉 computer-use agent 관점에서는 CaMeLs Can Use Computers Too: System-level Security for Computer Use Agents, AgentSentinel, RedTeamCUA가 관련됩니다. 이 논문들은 A2A 자체보다 “로컬 머신을 조작하는 에이전트가 악성 웹페이지, 문서, UI 텍스트, 파일 내용에 의해 오염될 때 어떻게 막을 것인가”를 다룹니다. 특히 CaMeLs는 trusted planning과 untrusted observation을 분리하는 구조를 제안하고, AgentSentinel은 민감 작업을 실시간으로 가로채는 방어 프레임워크를 제안하며, RedTeamCUA는 웹과 OS가 섞인 환경에서 indirect prompt injection을 실험합니다. ([arXiv][10])

실무 구현 쪽에서 흥미로운 자료도 있습니다. synapse-a2a라는 공개 프로젝트는 Claude Code, Codex CLI, Gemini CLI 같은 기존 CLI 에이전트를 수정하지 않고 Google A2A 프로토콜로 협업하게 하는 프레임워크를 표방합니다. 문서에는 Claude A2A server와 Codex A2A server를 띄우고, 한쪽에서 다른 쪽으로 메시지를 보내는 예시가 나옵니다. 이건 논문은 아니지만, 사용자가 말한 “Claude Code나 Codex 같은 로컬 에이전트를 A2A로 연결한다”는 구성이 이미 실험적 도구 형태로 나오고 있다는 증거입니다. ([GitHub][11])

읽을 우선순위를 정하면 이렇습니다. 1순위는 A2ASecBench입니다. A2A 프로토콜 자체의 공격 분류와 벤치마크라서 질문의 중심에 가장 가깝습니다. 2순위는 OpenClaw taxonomy 논문입니다. 로컬 개인형 에이전트가 어떤 식으로 신뢰 경계를 무너뜨리는지 가장 직접적으로 보여줍니다. 3순위는 ClawWorm입니다. A2A 또는 A2A 유사 메시징을 붙였을 때 payload가 에이전트 네트워크를 타고 전파될 수 있다는 위험을 가장 생생하게 보여줍니다. 4순위는 Skill-Inject와 Supply-Chain Poisoning 논문입니다. Claude Code·Codex 같은 로컬 개발 에이전트에서 skill과 파일 기반 확장이 얼마나 위험한지 다룹니다.

제가 보기에는 이 분야의 핵심 위협은 하나로 요약됩니다. A2A는 신뢰 전파 채널이고, 로컬 에이전트는 실행 권한 보유자입니다. 그래서 둘이 만나면 공격자는 “말”만 주입하는 게 아니라, 한 에이전트의 AgentCard, skill, artifact, task, memory, config, tool call을 통해 다른 에이전트의 로컬 실행권한까지 간접적으로 건드릴 수 있습니다.

실무적으로는 다음 방어가 중요합니다. AgentCard는 서명·검증하고, 에이전트 간 메시지는 “user/system/internal/inter-agent/external” 같은 출처 등급을 분리해야 합니다. A2A 토큰은 짧은 수명과 좁은 scope로 제한해야 하고, 로컬 파일·쉘·브라우저·키체인 접근은 정책 엔진과 사용자 확인을 거쳐야 합니다. skill은 서명, 출처 검증, 버전 고정, sandbox 실행이 필요하고, 한 에이전트가 받은 artifact를 다른 에이전트가 바로 실행하거나 해석하지 못하게 해야 합니다. IETF의 AI agent security draft도 에이전트가 secret에 직접 접근하지 말고 secret manager, keychain, TEE, temporary token을 쓰며, fine-grained policy enforcement와 microsegmentation을 적용하라고 권고합니다. 다만 이 문서는 peer-reviewed 논문이 아니라 아직 Internet-Draft 성격입니다. ([IETF Datatracker][12])

최종적으로, “내 로컬 컴퓨터에서 돌아가는 OpenClaw/Claude Code/Codex류 에이전트를 A2A로 연결할 때의 보안 위협”을 연구하려면 현재는 단일 논문 하나보다 아래 조합으로 보는 게 맞습니다.

A2ASecBench로 A2A 고유 공격면을 잡고, OpenClaw taxonomy와 ClawWorm으로 로컬 개인형 에이전트의 권한·전파 문제를 잡고, Skill-Inject / Supply-Chain Poisoning으로 Claude Code·Codex류 skill 생태계 위험을 잡고, CaMeLs / AgentSentinel / RedTeamCUA로 컴퓨터 점유형 에이전트의 OS-level 방어 모델을 잡는 방식입니다. 이 네 묶음이 지금 기준으로 가장 탄탄한 최신 문헌 지도입니다.
